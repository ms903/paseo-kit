Shows CPU, memory, GPU, disk and network usage for the selected Paseo host in the sidebar footer.

CPU, RAM, GPU and disk have individual icons and small meters when space permits. Download and upload speeds share one icon. The disk figure adds all local disks together. Readings turn yellow at 70 percent and red at 90 percent. On macOS the RAM color follows the system's memory pressure. Narrow sidebars drop network speeds first, then disk. Press the line for CPU, RAM and network history, per-device readings, uptime and load average.

**Details** opens a full page with available space for each disk and a GPU section. When Host Monitor is installed on several hosts, use Paseo's host picker in the page header to switch between them. Each host reports its own numbers and history.

Settings are saved on the selected host. In **Settings → Plugins → Host monitor**, choose which footer readings to show and how often to refresh. All five readings are enabled by default. Disabling GPU also stops its footer probe, and disabling all readings hides the footer and stops its polling. An open details page continues to request the full readings.

The daemon takes samples when a client displays the metrics. The app polls every two seconds by default, with five, ten and thirty seconds also available. CPU and network samples are shared for two seconds, disks for thirty seconds, and macOS memory for ten seconds. Disk reads run one at a time. The plugin keeps up to 90 samples in memory through an active viewing period.

The footer shows the busiest GPU's utilization and the device count on multi-GPU hosts, for example `×8 96%`. Drivers that only identify the hardware show a device count. The popover and **Details** list each detected card's utilization, used and total VRAM, and temperature as available. NVIDIA row numbers match `nvidia-smi` on Linux and Windows. Linux DRM cards use their sysfs names. Cards with the same model share a heading. Apple Silicon utilization comes from `ioreg`. Visible monitors share one host probe per ten seconds and check for absent devices at most once a minute.

Percentages below 10 show one decimal, so a nearly idle host reads 0.4% rather than 0%. On Linux, CPU usage comes from `/proc/stat`; I/O wait counts as idle and steal time, which a VPS loses to its hypervisor, counts as busy. Memory uses the available-memory figure from `/proc/meminfo` on Linux, so the page cache is not counted as used. On macOS, RAM follows Activity Monitor's Memory Used: app memory, wired memory and the compressor, read from `vm_stat`. Cached files are left out because macOS frees them as soon as an app needs the room; the popover shows them on a separate line. A Mac often runs at high usage with no shortage, so there the RAM color follows the kernel's memory pressure level (`kern.memorystatus_vm_pressure_level`): yellow at warning, red at critical, never because of the percentage alone. Sizes use binary units (KiB, MiB, GiB), so a 994.6 GB disk reads 926.3 GiB. Network speed sums all interfaces except loopback and common virtual ones (veth, docker, bridge). Disks are the filesystems in `/proc/mounts` backed by a block device (plus ZFS), each device counted once; network mounts, memory-backed filesystems and read-only images such as snap packages are left out. Disk percentages follow `df`: space reserved for root counts as neither used nor free. On macOS the disk is the APFS container of the root volume, so its usage covers every volume in the container (system, data, VM and others), and the popover labels it that way; apps that show the data volume alone report a little less. Network speed and the disk list need Linux. Outside Linux the disk display uses the root volume.

The plugin reads local system counters under the Paseo daemon's account. macOS memory uses short `/usr/bin/vm_stat` and `/usr/sbin/sysctl -n kern.memorystatus_vm_pressure_level` calls. Host details are served over the daemon's Paseo connection.
